# ADR-025: Canonical Research Consolidation & Unified Ingest Pipeline

## Status
Proposed (Draft for Review)

## Context
Our current workstation architecture separates qualitative research sweeps (news, earnings notes, catalysts) from deterministic models (DCFs, target sizing). This has created several inefficiencies:
1. **Date-Padded File Proliferation:** Research files in `backend/data/research/` use the format `{TICKER}_{DATE}.md`, creating multiple files for a single ticker over time (e.g. `SNDK_2026-05-02.md`, `SNDK_2026-05-19.md`, `SNDK_2026-07-02.md`). Tracking changes across files is difficult.
2. **Review Fragmentation:** Weekly/daily reviews generated by agent personas are stored in a gitignored `temp/` directory. They are useful for one-off viewing but are never back-propagated to individual ticker profiles.
3. **Inconsistent Ingestion:** Sweeps (like Grok responses) are pasted into temporary files (`temp/news-sweep-responses/grok/`) but are not automatically parsed to update individual research logs.

## Decision
We propose to unify and structure our data directories under a "Canonical Memory" standard:

### 1. Canonical Markdown Research Profiles
* Replace date-padded research files in `backend/data/research/` with a single canonical file per ticker: `backend/data/research/{TICKER}.md`.
* Each file will start with a structured YAML frontmatter block to store state, allowing automated scripts to read/write metrics easily.
* New sweeps and analyst notes will be appended as chronological sections (`## Research Update — YYYY-MM-DD`) at the bottom of the canonical file.

### 2. File Directory Reorganization
* **Consolidate Sweeps:** Relocate raw sweep responses under `backend/data/history/sweeps/` to keep a permanent, committed record of qualitative model responses.
* **Rationalize Reviews:** Maintain gitcommitted historical files in `backend/data/history/reviews/` instead of gitignored `temp/` directories, providing a permanent paper trail of weekly audits.

### 3. Automated Ingest Tooling (`py_services/consolidate_research.py`)
* We will write a python utility script to:
  1. Scan any new Grok responses pasted into `backend/data/history/sweeps/`.
  2. Parse the table rows and deep dives.
  3. Locate the corresponding canonical `research/{TICKER}.md` file.
  4. Parse the YAML header, update fields (like `lastUpdated`), and append the new qualitative findings to the history section.

## Consequences
* **Single Source of Truth:** One file per ticker holds all qualitative notes and history.
* **Git Cleanliness:** Git history becomes clean, tracking edits to a single `{TICKER}.md` file rather than untracked file clutter.
* **Programmatic Access:** Scripts can query YAML headers directly to display the latest consensus, conviction, and fair value figures on the frontend dashboard.

## Future Extensions
* **Sub-Strategy Linkage:** We will create automated checks to verify that strategy markdown profiles in `theses/sub_strategies/` are dynamically synced with the `subStrategyId` field in the `{TICKER}.md` frontmatter headers.
* **Track-Record Ingestion:** The `consolidate_research.py` script will eventually ingest and display the company's historical prediction hit-rate from `predictions.jsonl` directly in the `{TICKER}.md` profiles during research sweeps.
