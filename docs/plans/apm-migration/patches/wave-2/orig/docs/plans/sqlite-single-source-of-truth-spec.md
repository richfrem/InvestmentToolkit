# Spec: SQLite as the single source of truth

**Status:** Proposed. **Date:** 2026-10-09. **Plan:** [sqlite-single-source-of-truth-plan.md](sqlite-single-source-of-truth-plan.md). **Next ADR:** ADR-038 (written in WS0).

Words "must" and "must not" are requirements. Items marked **confirm** require the implementer to read the named code first, because this spec could not verify the detail.

## 1. Scope and non-goals

**In scope:** every Python, TypeScript and JavaScript path that reads or writes portfolio data, the docs and agent instructions that describe it, and the loading of research/analysis files into the ledger.

**Out of scope:** changing valuation logic, the Daily Brief ranking, broker integrations, or the frontend design beyond removing dead file-based behavior. Non-portfolio JSON (plugin manifests, tsconfig, schemas, test fixtures, API payloads) is untouched.

## 2. Data placement rules

1. A fact about holdings, targets, thesis state, trades, cash, price levels, alerts, valuations, policy or breakers has **one** home: `domain_model.sqlite`. Code reads and writes it only through the repositories (Python `domain_model/*_repository.py`, TypeScript `src/services/*Repository.ts`). No ad-hoc SQL in tools or routes.
2. A research or analysis record has **one** home: `intelligence.sqlite` (`intelligence_event`, `instrument`, FTS5 index).
3. Markdown, JSONL or JSON copies of (1) or (2) are **exports**: generated by a script, regenerable, never read by application code, never edited by hand.
4. A function that accepts a path "for compatibility" and ignores it must be removed from the signature (update all callers), not left in place.
5. Fallbacks to a file when SQLite is empty are forbidden. Empty SQLite is reported as empty (explicit state), never replaced with file data.
6. An `exists()` guard that silently skips work is forbidden for data that must exist. Missing data must fail loudly (exit non-zero or an explicit error response).

### 3.1 Thesis breakers

Definitions are one row per breaker; evaluated state is one row per breaker.

```sql
CREATE TABLE thesis_breaker (
  breaker_id        TEXT NOT NULL,
  investment_id     TEXT NOT NULL REFERENCES investment(investment_id),
  breaker_type      TEXT NOT NULL CHECK (breaker_type IN ('auto','manual')),
  metric            TEXT,                      -- required when breaker_type='auto'; one of AUTO_METRICS
  operator          TEXT NOT NULL CHECK (operator IN ('<','<=','>','>=','==','in')),
  threshold_json    TEXT,                      -- JSON scalar, or JSON list when operator='in'
  status            TEXT CHECK (status IN ('OK','WATCHING','TRIGGERED')),  -- manual breakers only
  status_set_at     TEXT,                      -- manual breakers only
  review_cadence_days INTEGER,                 -- manual breakers only
  created_at        TEXT NOT NULL,
  PRIMARY KEY (investment_id, breaker_id)
);
CREATE TABLE thesis_breaker_state (
  investment_id     TEXT NOT NULL,
  breaker_id        TEXT NOT NULL,
  status            TEXT NOT NULL CHECK (status IN ('OK','WATCHING','TRIGGERED')),
  current_streak    INTEGER,
  streak_start_date TEXT,
  last_evaluated_at TEXT NOT NULL,
  is_stale          INTEGER,                   -- manual breakers: review overdue
  PRIMARY KEY (investment_id, breaker_id),
  FOREIGN KEY (investment_id, breaker_id) REFERENCES thesis_breaker(investment_id, breaker_id)
);
```

**Confirm:** read `plugins/portfolio-advisor/scripts/update_thesis.py::validate_breaker` (fields `id`, `type`, `metric`, `operator`, `threshold`, `status`, `statusSetAt`, `reviewCadenceDays`) and `investment_screener/backend/py_services/thesis_breakers.py::_evaluate_auto_breaker` / `_evaluate_manual_breaker` (fields `currentStreak`, `streakStartDate`, `lastEvaluatedAt`, `status`, staleness). Add any further field they use (for example a required-streak length) as a column before writing the migration. Move `AUTO_METRICS`, `VALID_OPERATORS`, `VALID_STATUSES` into one shared module; `thesis_breakers.py` and `update_thesis.py` must import them, not redefine them.

`investment.thesis_breaker_status` stays a derived scalar (worst current status). It is written only by the breaker evaluator.

Repositories to add (Python and TypeScript, mirroring each other): `list_breakers(conn, symbol=None)`, `upsert_breaker`, `delete_breaker`, `set_manual_status`, `replace_breaker_state`, `list_breaker_state`.

### 3.2 Change log

`portfolio_change_log(entry_id, version, entry_date, note, created_at)` already exists. Define one repository function `record_change(conn, note)` that sets `version = MAX(version) + 1` and is called by every state-changing target edit: `update_targets.py --write`, `lock_and_normalize_targets.py --write`, `update_thesis.py` (role, thesis text, pillar target, breaker edits), `set_standing_decision.py`. A dry run must not write.

### 3.3 Roles

Canonical `lifecycle_status` values: `accumulate`, `trim`, `exit`, `initiate`, `watchlist`. `INACTIVE_ROLES` in `market_regime.py` also lists `exited` and `avoid`; keep them as accepted inactive values. Define the set once in `portfolio_io.py` and validate against it in every writer. Do not add a DB CHECK constraint in this migration (one existing row has a NULL status; decide on it explicitly).

### 3.4 Loaders

`portfolio_io.load_thesis_holdings()` must include a `thesisBreakers` list per holding (from `thesis_breaker`). `generate_portfolio_blueprint._load_thesis_map` must stop hard-coding `[]`.
